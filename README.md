# NET3106 Network Security — Chaotic-Map PRNG Assignment

Group assignment for **NET3106 Network Security**: implementing chaotic-map
pseudo-random number generators, visually inspecting their output, and
evaluating them with the NIST SP 800-22 statistical test suite.

This repo contains a strong (chaotic) and a weak (non-chaotic) logistic-map
PRNG, the visual tests (random walk + bitmap) used to inspect them, and the
NIST test pipeline used to formally confirm which one is cryptographically
usable.

## How the generators work

Both sources use the **logistic map**:

```
x_{n+1} = r * x_n * (1 - x_n)
```

| | Strong source | Weak source |
|---|---|---|
| Control parameter `r` | 3.99 (chaotic regime) | 3.5 (period-4 cycle) |
| Seed `x0` | 0.6013265 | 0.6013265 (same seed) |
| Transient discarded | first 1000 iterations | first 1000 iterations |
| Bit extraction | bit 30 of the IEEE-754 mantissa | same method |
| Output length | 1,000,000 bits | 1,000,000 bits |

Using the **same seed and extraction method** for both sources isolates the
control parameter `r` as the sole cause of weakness — this makes the
before/after comparison in Part E of the assignment clean to argue.

The bit-extraction method reads a bit from deep inside the IEEE-754 binary
representation of each `x` value rather than naively thresholding at 0.5.
A naive threshold keeps correlations from the map's parabola shape and
produces biased bits (~54%/46% split); the mantissa-bit method is
empirically unbiased (~50.05%/49.95% split, see Part A output).

## Running the pipeline

Run the parts in order — each one reads the files produced by the previous
step.

```bash
# Part A: generate the two 1,000,000-bit sources
python main.py

# Part B: random-walk visual test
python walkthrough.py

# Part C: random-bitmap visual test
python bitmap.py

# Part D: NIST SP 800-22 statistical test suite
python nist_tests.py strong_source.txt weak_source.txt
```

### Validating the NIST pipeline against the course benchmark files

Before trusting the results on your own generators, validate the pipeline
against the two reference files provided with the assignment
(`benchmark_good.txt`, `benchmark_weak.txt`, not included in this repo —
obtain them from the course portal):

```bash
python3 part_d_nist_tests.py benchmark_good.txt benchmark_weak.txt --validate
```

`benchmark_good.txt` should pass all 14 applicable tests and
`benchmark_weak.txt` should fail all 14. Exact p-values may vary slightly by
library version, but this pass/fail pattern must hold before you test your
own sources.

## Results summary

| Test | Strong source | Weak source |
|---|---|---|
| Bit balance | ~50.0% ones | 75.0% ones |
| Random walk | wanders freely, spreads out | collapses near the origin |
| Bitmap | structureless static | regular vertical stripes (period-4) |
| NIST SP 800-22 | 14 / 14 tests PASS | 0 / 14 tests PASS |

The weak source's `r = 3.5` sits in a period-4 cycle (well before the onset
of chaos at ~3.57), so it repeats a short bit pattern (`1110...`) forever.
This single parameter choice is enough to visibly bias the bit balance,
collapse the random walk, produce a striped bitmap, and fail every
statistical test — demonstrating why parameter selection is critical for a
chaos-based generator to be cryptographically usable.

## Course context

This is coursework for NET3106 Network Security (Applied Cryptography,
Weeks 9–10). It is intended purely to demonstrate how randomness quality is
evaluated (NIST SP 800-22) and is **not** a production-grade random number
generator. For real systems, use a vetted CSPRNG or your operating system's
random source.
